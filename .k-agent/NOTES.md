# Workspace notes

- RE toolchain is user-local: Ghidra in `~/tools/ghidra_12.1.4_PUBLIC`, jadx in `~/tools/jadx-1.5.6`, Android SDK in `~/Android/Sdk`, CLI tools in `~/.local/bin`. Load it with `. tools/env.sh`.
- Ghidra 12.1.4 is pinned because the GhidraMCP 2.0 extension is built for that version. Ghidra needs JDK 21, the system default stays JDK 26.
- Ghidra rejects project paths that contain a path element starting with a dot. Projects live in `analysis/ghidra-projects` inside the project folder, never under `.tmp/`.
- Headless GhidraMCP HTTP server default port is 8082. The Ghidra plugin port is 8080.
- jadx takes JVM options through the `JADX_OPTS` env var, not as a CLI flag. Use `JADX_OPTS=-Xmx6g`.
- MobSF flow: upload with `POST /api/v1/upload`, then `POST /api/v1/scan` with the returned hash, then poll `POST /api/v1/report_json` with form data `hash=`. The API key is printed in the container log as `REST API Key:`.
- MobSF container is named `mobsf`, bound to `127.0.0.1:8000`. Restart with `docker start mobsf`.
- App stack follows the onconature reference: npm only, Expo SDK 54, expo-dev-client, nativewind 2 with no preset in tailwind.config.js.
- `unstable_transformImportMeta: true` is required in babel-preset-expo, otherwise zustand 5 fails to bundle on Hermes.
- App id is `com.ktvsconnect.app`, app name `K Tvs Connect`. Original app id is `com.tvsm.connect.latam`.
- The scooter bluetooth is pure Java in the original app, package `com/tvs/bike/core/protocol` and `com/tvs/bluetooth`, not `com/tvsm`. `libBluConnect-Lib.so` is the Aptener BluArmor helmet SDK, not the scooter.
- The scooter service uuid is derived from the phone imei: `imei[0:8]-imei[8:12]-imei[12:15]9-5342-454E544F5251`. Read characteristic `00005354-...`, write `00005352-...`.
- MapLibre React Native is pinned to 10.4.2 because the project is on the legacy architecture and v11 dropped it.
- The map stack: Google Map Tiles API for the background map, Google Places API (New) text search for the search, Valhalla for routing, OpenFreeMap as the keyless fallback.
- The ANSV camera dataset is `https://fotodeteccion.ansv.gov.co/map/data/sast.json`, a public file with no key. Only `estado_operacion == "Operando"` is treated as active. Its infraction codes (C35, D02, ...) are the national ones and their wording is in `src/config/infractions.ts`; the app never shows a fine amount.
- Long decompiles run inside a docker container so they survive the session: `docker run -d --entrypoint java ... jadx.cli.JadxCLI`.
- The scratch of this project stays inside the folder: `tools/env.sh` points `GHIDRA_PROJECTS` at `analysis/ghidra-projects` and the scripts use `.tmp/` instead of `/tmp`.
- The phone is connected over usb as RCUSTSEQTSK7RKSW (model 2602DPT53G). `npx expo run:android` installs the dev build on it.
- The scooter bluetooth frame tables are in `src/ble/frames.ts`, ported from `com/tvs/bike/core/protocol/apache/*`, and covered by `src/ble/parser.test.ts`.
- The frames that arrive over ble are xored with `0xEA` (the new families) or `0xEB` (the legacy ones) before the parser sees them, and the tail byte is replaced by `0xFF`. The checksum sits in the second to last slot of the decrypted frame.
- The app icons are generated by `sharp` from an svg in `.tmp/icongen/generate.js`, and `npx expo prebuild --clean` has to run again for the native resources to pick them up.
- Every screen renders through `src/components/ScreenContainer.tsx`, which owns the safe area insets. Do not pad for the system bars by hand in a screen.
- The MIUI phone can revoke INJECT_EVENTS for the adb shell, then `adb shell input tap` fails with exit 255. Unlock the phone and enable "USB debugging (Security settings)" to get the permission back.
- The docker apk build caches gradle in the named volume `k-tvs-connect-gradle`, seeded from `~/.gradle`. Mounting `~/.gradle` directly breaks the gradle daemon.
- The expo dev client shows a welcome sheet on the first launch that only a real touch dismisses, it blocks synthetic `adb input tap`.
- Metro caches aggressively in /tmp/metro-cache, so a stale bundle can hide a code change. Start it with `--clear` on a fresh port when the bundle looks wrong.
- The `write` tool reports type diagnostics against a stale snapshot in this build, so trust `npx tsc --noEmit` over the tool output.
- The cluster does its own routing: the phone only sends the destination address as text over the write characteristic, never the geometry.
- The Valhalla summary length comes back in kilometres whatever the units parameter says, so the route distance is measured from the encoded shape with `src/utils/polyline.ts`.
- The Photon geocoder is gone, the search is Google now. The search key is in the gitignored `.env.local` as `EXPO_PUBLIC_GOOGLE_MAPS_API_KEY`, the tiles key as `EXPO_PUBLIC_GOOGLE_TILES_API_KEY`, and `tools/verify-bundle.sh` allows both by sha256.
- Valhalla reports the summary length in kilometres whatever the `units` parameter says, so the distance comes from the encoded shape. Its `exclude_polygons` takes plain rings, not GeoJSON. Only the polygons are sent: `exclude_locations` removes the whole closest road, the polygon removes just the roads that cross a 50 m circle around the point. Measured: a route passes 37 m from a camera without the ring and 70 m with it.
- The cluster shows the rider name and the phone clock, not the route. The phone sends the destination address as text over the write characteristic and the cluster routes with its own engine.
- The official app sends no notification text to the cluster, only the social media counters and the media metadata.
- The app palette is TVS red and black: primary `#E4002B` in the light theme, `#FF2743` in the dark one, and the icon is a motorcycle on a red tile.
- The navigation to the bike is two packets: `5A 4E` for the control (the distance to the next turn, the time left, the distance left, the pictogram) and `5B 4F` for the instruction text.
- The location lives in one global store with a watch, and everything that moves reads it: the map, the camera distances, the remaining distance and the navigation.
- Google Maps Platform has no $200 credit any more: since 1 March 2025 it is per-SKU monthly free caps that reset on the 1st. Confirmed from the printed pricing page in maps-pricing/: Essentials 10K, Pro 5K, Enterprise 1K free calls per SKU per month. Compute Routes Essentials 10,000; Compute Routes Enterprise (motorcycle) 1,000; Navigation Request 1,000 destinations; Geocoding 10,000; Map Tiles 2D 100,000; Maps SDK Unlimited at $0. There is no hard spend cap for Maps Platform, only per-day quotas, and Google tells you to set the quota at cap/31.
- Google's terms forbid caching the route geometry and forbid turning their driving times into synthesized speech, which is exactly what the app does when it builds the cluster instruction packets. That is why the app keeps Valhalla for the routes that reach the bike.
- The Google Geocoding API does not do category search: "gasolinera" with a bias returns "Colombia" and "Terminal de Transporte" returns terminals in other cities. The Places API (New) text search is the one that finds a category, so the key has to allow it in the api restriction, not only the geocoding api.
- A Google key restricted to Android apps works on REST calls only when the request carries `X-Android-Package` and `X-Android-Cert`. Without them the answer is `REQUEST_DENIED` "This IP, site or mobile application is not authorized to use this API key".
- MapLibre RN 10.4.2 releases the camera tracking when the rider drags the map and never tells javascript (`onCameraTrackingDismissed` is empty), and while `followUserLocation` is true the Camera never applies its `centerCoordinate`. To take the camera back to the rider, remount the Camera with a changed key.
- On Android, `PointAnnotation` draws its child into a bitmap and adds it to the style, so the marker is invisible if the style is not loaded yet and the touch never reaches the child. Use `MarkerView` for every marker that has to be seen or tapped.
- The rider wants one tap on the map to open a menu on the point, not a long press, and one tap on an avoid point to open a small menu to delete it.
- A map marker must only answer the touch on the icon itself. The rider complains when a tap to the side of the icon opens it, because it eats the gesture of moving the map. The touchable is the 22 dp body and nothing else.
- The name of the focused camera goes in a band, not on the marker. A chip on the marker moves the icon when the text changes and the marker view is clipped by the plugin.
- The maplibre `centerCoordinate` is `[lon, lat]` while the position of the app is `[lat, lon]`. The mix only shows when the camera stops following the rider, and then the map goes blank.
- The infraction codes of the cameras are the national ones (Ley 769 de 2002, the A to I groups of the autoliquidacion table). The wording is in `src/config/infractions.ts`, taken from the table of the Secretaria Distrital de Movilidad.
- The Map Tiles API key has no application restriction on purpose: the tiles are fetched by the native maplibre loader, which cannot send the `X-Android-Package` headers an android restriction needs. The daily quota of 3225 (100.000 / 31) is what keeps it under the free cap.
- The ANSV camera dataset has no field for the sense of a camera, but the free text of `direccion` carries it: "Sentido Sur - Norte", "sentidos NORTE - SUR", "(N-S)". The pair is written from where the watched traffic comes to where it goes, which the warning signs of the camera confirm. Only 413 of the 1342 cameras publish one.
- A camera that watches one sense sees the front of the bike when the rider goes with that traffic, and the plate when the rider goes the other way. So the app only avoids a camera when the route goes in the direction the camera watches.
- The camera exclusion radius was 100 m and the corridor a straight line, and the router answered "no path could be found". The radius is now 25 m, the corridor is the route itself, and the route is computed twice: once without cameras to know the direction of travel, once with the cameras that are in the way.
- The expired cameras of the ANSV (Vencida, Renovada - Expirada, Prorrogada - Vencida) are still on the road, so the app keeps them, shows them in orange and avoids them.
- A marker view that has a sibling drawn on top of the icon can hide the icon completely on Android. The arrow that shows the direction of a camera has to live inside the touchable, not next to it.
- The rider wants every action on a map object in two taps: tap the camera and then the option. So a camera opens a small menu with the actions, not the full card, and every menu has a Cancel row.
- There are two routes to a destination: the short one that cuts between neighbourhoods (the motor scooter profile) and the safe one that stays on the main roads (the auto profile). Both avoid the cameras that are in the way, both are drawn on the map and the one that is selected is the opaque one.
- The route was asked again on every position update, which is every two seconds while riding. It is asked again now when the rider has moved 200 metres.
- The navigation frame the cluster reads is `5A 4E` and it has to carry the checksum, the same as the original writes it. Without the checksum the cluster drops the frame, and the guidance never reaches the bike.
- The original sends that frame every 400 milliseconds while the navigation runs, not on every position, so the distance to the turn moves while the phone is in the pocket.
- For the apache family the original never writes the destination address, the traffic sequence or the road name to the cluster, only the name, the mobile data and the navigation.
- The pictogram ids of the cluster are a numbering of their own. The original maps the id of the map provider to them in `ApacheUtils.mapPictoIdForApache`, and the semantic name of every cluster id does not exist in the original app, so it needs a real cluster to be confirmed.
- The app keeps the process alive with its own foreground service, of the `connectedDevice` type, with a wake lock, in the local module `modules/ktvs-cluster`.
- MIUI answers the battery optimisation intent with its own per app power screen, where the option the rider needs is "No restrictions".
